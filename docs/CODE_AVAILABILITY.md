# Section 2.17. Code availability

## Submission wording when this archive is supplied as Supplementary Software 1

Use after attaching the actual archive to the submission:

"Code for source reconstruction, statistical analysis, frozen-model evaluation and figure generation is provided in Supplementary Software 1 (version 1.0.0-rc2). The package includes model coefficients and training-only predictor scaling, random seeds, software requirements, source and figure provenance, and executable numerical checks. Installation, example runs, measured runtimes and the scope of reproducibility validation are documented in the README and accompanying validation reports."

The author has authorized public sharing while the software license remains pending institutional approval. No open-source license is granted by this release. If the final submitted archive is revised, update the version and integrity manifest in both the statement and package.

## Wording for the final repository release

Replace the two bracketed fields only after the public landing page and its archived version have been verified:

"Code for source reconstruction, statistical analysis, frozen-model evaluation and figure generation is available at [version-specific public archive URL or DOI] (version [published version]). The release includes the frozen model coefficients and predictor scaling, analysis specifications, random seeds, software requirements, source-data provenance, figure-source mappings and executable numerical checks. The software license remains pending institutional approval; source data retain their separate terms, as documented in the release."

If a journal supplementary-software ZIP is used instead of a public deposit, identify the actual uploaded supplement and version in place of the public archive reference. Do not state that code is publicly available before the files are accessible.

## What this package supports now

Version 1.0.0-rc2 is a local release candidate. It contains real study code and artifacts, rather than an empty repository template. New checks are identified separately from archived checks. `RELEASE_STATUS.json` states the current executed scope and remaining author decisions. This preparation does not revise the main manuscript, register a DOI or publish files.

## Evidence for the reporting approach

Nature Medicine's reporting standards require access to central custom code for editorial review and a Code availability statement. Nature Portfolio's software guidance asks for versioned source, documentation, installation information, dependencies, example inputs and runtime information. Persistent archiving and an open-source license are recommended practices; no particular hosting service or software license is mandated.

See [Nature Medicine reporting standards](https://www.nature.com/nm/editorial-policies/reporting-standards) and [Nature Portfolio code and software guidance](https://www.nature.com/documents/GuidelinesCodePublication.pdf). The detailed policy review, access date and distinctions between requirements and recommendations are in `JOURNAL_REQUIREMENTS.md`.
